# HANDOFF — 2026-07-30 LATE (smoke fixes on `feat/firm-readiness`: invite delivery honesty + admin firm assignment)

A smoke run of the branch on the :3100 prod bundle found two real defects and one process gap. All three are closed on this branch (commit `fix(firms): honest invite delivery reporting + an admin path for firm membership`), rebuilt at HEAD, and re-verified by REST + Mongo the same way the smoke run found them.

1. **`firms.invite` claimed delivery it could not know about.** `Mailer.send` resolves as soon as the message is QUEUED (`sendNoWrap` ends in `setImmediate(() => Email.sendAsync…)`), so `await`ing it can never reject on an SMTP failure — the old `sent` array always contained every syntactically-valid address and the `catch { invalid.push(email) }` arm was dead code for delivery errors. On a workspace with no transport (local, staging) or a blocked one (**prod's M365 tenant block**) a firm owner saw "invites sent" and the firm never populated. Fix is in `inviteToFirm`, NOT the stock mailer: pre-flight `isSMTPConfigured()`, and return `{ queued, invalid, undelivered, emailDelivery: 'queued' | 'unavailable', inviteUrl }`. `queued` means handed to the transport, never "delivered" — that distinction is now in the type, the i18n copy and the DTO comment. `FirmOnboardingPage` keeps the owner on the invite step and shows the invite link when `emailDelivery === 'unavailable'`.
2. **There was no supported way to write `customFields.firmId`.** Admin `users.update` answered `success: true` while dropping the payload (`saveCustomFields` validates against `Accounts_CustomFields`, empty on every workspace we run, and early-returns doing nothing). New **admin-only `POST /v1/firms.setUserFirm`** (`{userId|username, firmId|null, firmName?, firmRole?}`) is the supported path: it writes through the Users model, resolves `firmName` from the firm team when one exists, returns `firmTeamFound: false` for team-less OmnisAI org cohorts (an orgId has no team behind it), and `firmId: null` clears the whole firm-owned key set. Deliberately NOT gated on `Firms_SelfServe_Enabled` — cohorts must be fixable before the flag goes on. It does NOT change firm-team room membership. The silent door is closed with it: `saveCustomFields` now throws `error-firm-custom-fields-readonly` for `firmId/firmName/firmRole/firmIdSource` (one marked MATTERCHAT guard call + import), which also stops any user self-assigning into another firm via `users.updateOwnBasicInfo` if an admin ever declares a matching custom field.
3. **The smoke run tested a bundle one commit behind the tree.** Rebuilt at HEAD and re-ran the invite burn-down against the BaseRaw-wrapped `consumeUseById`: redemption still burns 1→exhausted, the second redemption fails `error-invite-expired`, adoption stays bounded to the successful redeemer, and `_updatedAt` now moves on consume. **Rule: check the `Commit Hash:` line in the SERVER RUNNING banner against `git rev-parse HEAD` before trusting any REST result on :3100.**
